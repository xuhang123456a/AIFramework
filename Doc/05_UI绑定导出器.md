# 05 · UI 绑定导出器（T3-2）

> 结论：场景/预制体里的 `UIBindNode` 语义标记现在可以一键导出成 `*.bindings.json`，`tools/viewgen` 不再只能从手写描述起步；导出器对现有 4 份描述的 JSON 组装能做到逐字节复现（§五，离线验证），但「在真 Unity 里点菜单」尚未跑过（§六）。

## 一、组成

| 文件 | 角色 |
|---|---|
| `src/Adapters/AIFramework.Adapters.Unity/Runtime/UI/UIBindNode.cs` | 控件语义标记 + `UIBindKind`；Runtime 程序集不引用 UGUI |
| `src/Adapters/AIFramework.Adapters.Unity/Runtime/UI/UIViewDescriptor.cs` | 面板根上的描述：面板名 / 视图命名空间 / 摘要 |
| `unity/Assets/AIFrameworkDemo/Editor/UIBindExporter.cs` | 菜单 `AIFramework/导出 UI 绑定描述`：收集、校验、写 JSON |
| `unity/tools/shims/*.cs` | 形状桩追加 `Selection.activeGameObject` 与 `Application.dataPath`（仅离线编译用） |

## 二、场景标注规则

1. 面板根对象挂 `UIViewDescriptor`：`panelName`（可空，空则用根对象名去掉后缀 `Panel`）、`viewNamespace`（必填）、`summary`（可选）。
   一个面板一个根；一个场景有多个面板时，每个面板根各挂一个。
2. 按钮 / 文本 / 列表容器挂 `UIBindNode`，填 `semanticName`（面板内唯一，决定生成成员名）、`kind`、`target`。
3. `kind` 与 `target` 必须是下列组合，导出器逐个校验；不匹配时抛 `InvalidOperationException`，消息里带面板名、语义名与当前 `target` 的真实类型。

| kind | 合法 target |
|---|---|
| `Event` / `EventWithInt` | `Button`（或挂着 `Button` 的物体） |
| `Text` / `Number` | `Text`（或挂着 `Text` 的物体） |
| `List` | `Transform` / `RectTransform`（列表容器） |
| `Visible` | 任意（通常是 `RectTransform`） |

## 三、导出规则

- 入口：菜单 `AIFramework/导出 UI 绑定描述`（priority 12）。
- 选中面板根 → 只导出该面板；未选中 → 导出当前场景里所有 `UIViewDescriptor`。两种情况都向下收集 `UIBindNode`，含未激活节点。
- 按 `semanticName` 序数排序后写文件，保证 diff 稳定；重名立即中止并列出重复项（语义名 + 物体名）。
- 输出 `Assets/AIFrameworkDemo/Bindings/<Panel>.bindings.json`：UTF-8 无 BOM、2 空格缩进、`\n` 换行；写完 `AssetDatabase.Refresh()`。
- 面板名优先取 `UIViewDescriptor.panelName`；为空时取根对象名去掉后缀 `Panel`（`SignInPanel` → `SignIn`）。结果不是合法标识符则报错。

## 四、从导出到生成（手动步骤）

1. 在 Unity 里打开场景，选中面板根对象（如 `SignInPanel`）。
2. 执行 `AIFramework/导出 UI 绑定描述`；控制台应打印 `已导出 …/SignIn.bindings.json（N 条绑定，面板 SignIn）` 与下一步提示。
3. 把 `Assets/AIFrameworkDemo/Bindings/SignIn.bindings.json` 拷到切片目录覆盖同名描述，例如 `src/AIFramework.Features/Feature.DailySignIn/SignIn.bindings.json`。
4. 在仓库根执行：

   ```powershell
   dotnet run --project tools/viewgen -- src/AIFramework.Features/Feature.DailySignIn/SignIn.bindings.json
   dotnet run --project tools/viewgen -- --all
   ```

5. 回到 Unity，等 `AssetDatabase.Refresh` 与脚本重编译结束，确认 `I<Panel>View.g.cs` / `<Panel>ViewBinder.g.cs` 与场景标注一致。

> 第 3 步为什么手动：导出器只负责「场景 → staging JSON」。文件落到哪个切片属于工程归属决策，编辑器工具不跨目录写 `src/` 源码。

## 五、推断不出的字段与回填规则

viewgen 的 `List` 必须带 `itemType`，每条绑定还可带 `parameter` / `summary`。这些是纯逻辑侧的 C# 元数据，场景控件没有可靠来源，导出器按面板名找旧描述（先 `src/**/<Panel>.bindings.json`，再 `Assets/AIFrameworkDemo/Bindings/<Panel>.bindings.json`），按 `semanticName` 继承：

| 字段 | 旧描述里没有时 |
|---|---|
| `List.itemType` | 直接报错，提示在哪份文件补同名条目；新列表首次接入需先写一条 |
| `EventWithInt.parameter` | 不写入，viewgen 默认 `dayIndex` |
| 每条 `summary` | 不写入（该条没有注释） |
| 面板 `summary` | 用 `UIViewDescriptor.summary`；它为空时才沿用旧描述 |

离线验证（无 Unity）：对 `SignIn` / `Shop` / `Quest` / `Mail` 四份现有描述，用同一套继承 + 组装逻辑重建，与原文件逐字节一致；随后 `dotnet run --project tools/viewgen -- --all` 仍返回 0。这证明 JSON 层逻辑正确，不等于菜单在真 Unity 里可点（见下节）。

## 六、限制与未验证点

- **未在真实 Unity 里点过菜单**：本机形状校验只证明代码对 `UnityEngine` / `UnityEditor` 的 API 形状能编译；菜单注册、`Selection.activeGameObject`、`AssetDatabase.CreateFolder` 的真实行为仍需在编辑器里各跑一次。
- 只处理 `Selection.activeGameObject` 指向的对象，或当前打开场景里的对象（含 Prefab 编辑模式下的预览场景）；在 Project 窗口直接选 `.prefab` 资产能否导出未在真机验证。
- 不修改 `.prefab` / `.unity`，也不自动写 `src/`；导出与拷贝是两步。
- `UIBindNode` 只是标记，不参与运行期事件绑定；事件连线与列表池仍由 `<Panel>ViewBinder.g.cs` 和项目侧 `partial` 实现负责。
- 一个面板一个 `UIViewDescriptor`；未选中时的导出以描述组件为锚点，不依赖层级路径，调整层级不影响导出结果。

## 七、排错

| 现象 | 原因 / 处理 |
|---|---|
| 报「当前场景没有可导出的面板」 | 场景里没有 `UIViewDescriptor`；给面板根挂上再导出 |
| 报「没有 UIViewDescriptor」 | 选中了子节点，或面板根漏挂组件；选中面板根或补组件 |
| 报「语义名重复」 | 同一面板下有同名 `UIBindNode`；按消息里的物体名改名 |
| 报「List 缺少 itemType」 | 旧描述里没有同名 List；先在切片描述里补 `itemType` 再导出 |
| 报 target 类型不匹配 | 按 §二 的表格修正 `kind` 或 `target` |
